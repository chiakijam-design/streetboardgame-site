- GTM: GTM-5VMKFTGP（2026-09-16確認時はGoogleタグとClarityの2タグ。ゲームイベントタグの追加は不要）
- GA4カスタム定義: 「ゲーム種別」= game_type、「参加者区分」= player_role。どちらもイベントスコープで2026-09-16に登録済み。

## 数え方

1. 訪問者数: 対象期間全体の「総ユーザー数」。セッションや表示回数とは別。
2. プレイ人数: イベント名が完全一致で `game_play` の「総ユーザー数」。イベント数を人数にしない。
3. 完了人数: `game_result` の「総ユーザー数」。開始・回答・完了を混同しない。
4. 売上成果: 引き続き `purchase` のみ。game_playを購入キーイベントにしない。

`game_play` は少なくとも1問に回答した場合だけ送信する。通常版出題者はローカルで答えを選択・受付した時点、通常版回答者とLIVE参加者はサーバーに回答を受理された時点。
ページ表示、名前入力、参加・開始ボタンだけでは発火しない。失敗した回答、未承認のWebSocket送信では発火しない。

| game_type | player_role | 区分 |
| --- | --- | --- |
| challenge | creator | 通常版の出題者 |
| challenge | participant | 通常版の回答者 |
| live_challenge | host / subject | LIVE版の配信者・本人回答者 |
| live_challenge | viewer | LIVE版の視聴者 |

全体のプレイ人数には出題者も含む。回答する側だけを見る場合は participant / viewer でフィルタする。
区分別・日別・月別の人数を足して全体人数にしない。同じ人が複数区分・複数日に現れるため、全体期間の総ユーザー数を別に取得する。

重複イベントを抑えるため、同一タブのsessionStorageでは日本時間の日付・ゲーム種別・区分ごとに1回に制限する。日が変われば回答時に再送するため、毎月1日・16日など任意の日付境界で期間集計できる。複数日・複数タブの重複排除はGA4ユーザー識別に任せる。
送信パラメータは game_type、play_mode、player_role、play_criteria の定型値のみ。名前・回答内容・ルームコード・管理トークンは送信しない。

- 「レポート → エンゲージメント → イベント」で `game_play` を検索し、対象期間の「総ユーザー数」を読む。
- 種別を分ける場合は探索でイベント名 = game_play、行 = ゲーム種別／参加者区分、値 = 総ユーザー数を指定する。
- 同じ探索で「ユーザーの最初の参照元 / メディア」を追加すると、プレイした人の初回流入元が分かる。
- 標準レポート・カスタム定義への反映には処理待ちがある。未表示をゼロ人と断定しない。

## テスト除外・限界

- localhost / プレビューではタグを読み込まない。
- 本番の手動・Codexブラウザー確認は必ず `?analytics=exclude` を付けて開始する。localStorageに除外状態を保存する。
- navigator.webdriver === true の自動ブラウザーは本番でもGA4/GTMを読み込まない。analytics=includeでも上書きしない。
- ローカルE2Eは計測送信をメモリー配列へ置き換え、Googleへの通信を遮断する。本番に試験イベントを混ぜて受信確認しない。
- Cookie拒否、広告ブロッカー、端末・ブラウザー変更などのため「実在する人間の厳密な人数」ではなくGA4が識別できた人数。
- 2026年7月はCodexテスト混入の申告があるため基準に使わない。過去の回答イベント欠損はこの変更で遡及復元できない。
